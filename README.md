# Mavora, Phase 1 + 2 (real build)

Static site for Cloudflare Pages + your Mavora Firebase project.

## Setup
1. Firebase Console: create project, enable **Authentication** (Email/Password + Google) and **Firestore**.
2. Add a Web app, paste its config into `firebase-config.js`.
3. Auth > Settings > Authorized domains: add your Pages domain (and `localhost`).
4. Deploy rules/indexes: `firebase deploy --only firestore` (uses `firestore.rules`, `firestore.indexes.json`).
5. Push this folder to Cloudflare Pages (no build step; output dir `/`). HTTPS is required for PWA install.
6. First admin: set the custom claim `admin: true` on your uid with the Firebase Admin SDK (never from the browser).

## Built now
Email + Google sign-in, password reset, buyer profile, seller onboarding (shop / no-shop pickup location, private data split from public profile), Light/Dark/System theme saved to your Firestore profile, PWA (manifest, icons, service worker, offline page, install button), CBM footer hidden in installed app, Firestore rules.

## Notes
- Service worker caches only the static shell; account data, orders and Firebase traffic are never cached.
- Cloudinary uploads and all provider keys must go through a Worker (Phase 7), not this frontend.
- Bump `V` in `sw.js` on each release to push updates.

## Phase 2 additions (setup)
1. **Republish rules**: Firebase Console > Firestore > Rules > paste the new `firestore.rules` > Publish.
2. **Indexes**: the first time the homepage loads, the browser console may print a link for a missing index (products/services by status + date). Click it, press Create index, wait ~1-2 minutes. (`firestore.indexes.json` lists both.)
3. **Photos (optional)**: create a free Cloudinary account, then Settings > Upload > Add upload preset > set Signing mode to **Unsigned**. Add to the bottom of `firebase-config.js`:
   `export const cloudinary = { cloudName: "YOUR_CLOUD_NAME", uploadPreset: "YOUR_PRESET" };`
   (No secret key is used in the browser. Without this, listings publish without photos.)
4. **Support email (optional)**: add `export const supportEmail = "you@example.com";` to `firebase-config.js`.
5. Re-upload the folder to Cloudflare Pages, then hard refresh (Ctrl+Shift+R).

## In-app notification centre
- The bell opens a private notification centre with an unread count and mark-all-read action.
- New-message notifications are written atomically with the message.
- Order placement and order status notifications are generated by the Cloudflare Worker using its Firebase service account.
- Notifications are stored under `users/{uid}/notifications`; owners can read, mark read, or delete their own records.
- Email and browser push notifications are not included.
- Deploy the updated `firestore.rules` and `worker.js` to enable all notification events.

## Phase 3 (orders)
- Worker lives in `../mavora-worker/worker.js`. It holds all private keys (Firebase service account now; Paystack/Shipbubble keys later). There is no API-key screen in the website.
- Add to `firebase-config.js`: `export const apiBase = "https://YOUR-WORKER.workers.dev";`
- Orders are created only by the Worker (price, stock, order number and status rules are enforced server-side). Rules deny all client writes to `orders`.
- Shop links: sellers pick a link name in Dashboard > Shop settings: `/#/shop/<name>`.


## Location features (buyer + seller)
- Buyers can opt in to browser/device location on the homepage to see products within 50 km. They can also search by manually entering a city or area without granting GPS permission.
- Sellers can optionally add an approximate public map pin to a product. Coordinates are rounded to three decimal places (roughly 100 m) before publication; do not use this for a private home address. Existing listings need to be edited and pinned before they can appear in GPS-based nearby results.
- At checkout, buyers can optionally attach their current GPS coordinates to the delivery details while still entering a complete written address. The buyer and seller can open the saved delivery pin from the order details.
- Browser geolocation requires HTTPS (Cloudflare Pages provides this) or localhost. Permission is requested only after the user taps a location button. If permission is denied, manual area/address entry remains available.
- Deploy the updated `firestore.rules` in Firebase Console and deploy the updated `worker.js` to the configured Cloudflare Worker so delivery coordinates are validated and preserved in orders. Upload the updated site files to Cloudflare Pages.
